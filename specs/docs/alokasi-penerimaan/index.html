Request Mutasi

Test case: Request Mutasi sampai alokasi mutasi (SUSTAIN → STM)
  1. Request: klik Tambah. Tgl 18-11-2026, Dari Bank BCA Sustain, Ke Bank BCA STM, Keterangan "Pengembalian dana talangan ke STM", Nilai 15.000.000 → Simpan. Hasil: MTS-261100007 berstatus Menunggu Approval.
  2. Approval: menu Approval Mutasi → Approve MTS-261100007. Hasil: status Approved.
  3. Upload rekening koran bank asal: Penerimaan → Alokasi → Upload Rekening Koran → rekening BCA - 436.400.0300 - Bank Sustain, file rekening_koran_BCA_SUSTAIN_18112026.csv → Preview → Proses. Hasil: baris "KE 4363005287 SENTRAL TEHNOLOGI" uang keluar 15.000.000, status Open.
  4. Alokasi baris keluar: klik Alokasi → jenis Mutasi 15.000.000 → Simpan. Hasil: baris masuk menu tampungan Mutasi.
  5. Proses baris keluar: Penerimaan → Mutasi → baris itu → Proses Mutasi → No Request MTS-261100007 (cocok) → Simpan. Hasil: realisasi MTR-261100003 dibuat beserta jurnal; Request Mutasi berstatus Terealisasi.
  6. Upload rekening koran bank tujuan: Alokasi → Upload → rekening BCA - 436.300.5287 - Bank STM, file rekening_koran_BCA_STM_18112026.csv. Hasil: baris "DARI 4364000300 SENTRAL SUSTAINABILITY" uang masuk 15.000.000.
  7. Alokasi baris masuk → jenis Mutasi 15.000.000.
  8. Proses baris masuk: Penerimaan → Mutasi → baris masuk → Proses Mutasi → pilih request yang sama, MTS-261100007 (cocok). Hasil: ditautkan ke MTR-261100003; kolom Proses kedua baris menampilkan MTR dan jurnal per sisi (Lihat jurnal).
Urutan boleh terbalik: kalau rekening STM diupload dan diproses duluan, baris masuk yang membuat realisasi, lalu baris keluar ditautkan. Uji negatif: request yang bank asal/tujuannya beda dengan rekening koran → ditolak; rollback baris yang sudah diproses → ditolak.
Modul yang sudah berjalan (request_mutasi): request → approval → realisasi. Form request disederhanakan untuk mockup. Realisasi sekarang dilakukan dari tampungan Mutasi (rekening koran).

Ringkasan Perubahan

Yang baru
  • 4 sub modul tampungan di menu Penerimaan: Pengembalian Kasbon, Mutasi, Transaksi Bank, Pembayaran. Isinya semua alokasi berjenis itu dari menu Alokasi (sumber: tr_alokasi_split.jenis_alokasi 3, 4, 5, 6).
  • Tampilan dan aksi meniru Unlocated Penerimaan: filter tanggal & bank, tabel, centang, Rollback Data Terpilih (kembali Open di Alokasi).
  • Kolom baru Nominal Alokasi di tabel tampungan: 1 transaksi bisa dipecah ke beberapa jenis, jadi nominal yang masuk ke tampungan bisa lebih kecil dari debit/kredit transaksinya. Baris total di bawah tabel, dipisah uang masuk dan uang keluar.
  • Detail alokasi (View) di menu Alokasi diberi link ke menu tampungan tiap jenis.
  • Mutasi: kolom Proses, satu tombol Proses Mutasi untuk baris keluar dan masuk. User memilih Request Mutasi yang sudah di-approve (bank asal harus sama dengan rekening untuk baris keluar, bank tujuan untuk baris masuk). Belum ada realisasi → sistem membuat MTR + jurnal (tanggal & nilai aktual dari rekening koran). Sudah ada realisasi dari sisi lain → baris ditautkan ke realisasi itu. Kolom Proses menampilkan MTR dan link Lihat jurnal.BARU
  • Transaksi Bank: kolom Proses → form Transaksi Bank terisi dari rekening koran (jenis, tanggal, company, COA bank, nilai); user memilih COA lawan. Data Transaksi Bank menampilkan baris rekening korannya.BARU
  • Baris tampungan yang sudah diproses (MTR / KK / KM) tidak bisa di-rollback sebelum dibatalkan di modulnya.BARU
  • Unlocated Penerimaan: dua tombol, Pindahkan ke Penerimaan Piutang Invoice (jenis jadi Penerimaan Piutang, tab Invoice) dan Pindahkan ke Penerimaan Piutang Kwitansi Deposit (jenis jadi Deposit, tab Kwitansi Deposit; kwitansi opsional, 1 data per kwitansi). Alokasi Unlocated yang belakangan diketahui sebagai pembayaran invoice diubah jenisnya jadi Penerimaan Piutang (draft), tanpa rollback dan alokasi ulang.BARU
  • Rollback dari tampungan hanya membatalkan alokasi di menu itu. Alokasi lain di transaksi yang sama tetap, dan transaksinya berstatus Sebagian · sisa Rp … di menu Alokasi. Tombol Alokasi muncul lagi untuk mengalokasikan sisanya saja. Di sistem sekarang rollback menghapus semua alokasi transaksi itu.BARU
Sudah diputuskan
  • Jurnal All (AP-R-37, 23-Nov-2026): semua jurnal dari Alokasi masuk staging Jurnal All (belum posting) lalu diposting. Tampilan mengikuti Jurnal All sistem (card dan tab per sumber, filter Tahun / Bulan / Company, + Post → Detail jurnal → Posting; yang sudah diposting di Report Jurnal All). Tab Penerimaan + filter Kategori Transaksi (Penerimaan Piutang / Unlocated Penerimaan); tab baru Jurnal Bank (Mutasi, Transaksi Bank; Kategori & Arah); Pengembalian Kasbon di tab Expense Report. Unlocated yang sudah diproses boleh dipindah walau jurnalnya belum diposting.BARU
  • Nama menu sesuai jenis alokasi: Pengembalian Kasbon, Mutasi, Transaksi Bank, Pembayaran.
  • Kolom Nominal Alokasi juga dipakai di Unlocated Penerimaan (dan Alokasi Kalibrasi) yang sekarang.
  • Jenis alokasi dibatasi arah dana. Uang masuk: Penerimaan Piutang, Unlocated Penerimaan, Pengembalian Kasbon, Alokasi Kalibrasi, Deposit. Uang keluar: Pembayaran. Keduanya: Mutasi, Transaksi Bank.
  • Rollback dari tampungan: pilihan B, hanya alokasi di menu itu yang dibatalkan; sisanya jadi status Sebagian.
  • Mutasi tetap wajib lewat Request Mutasi + approval (menunggu konfirmasi atasan).
  • Dashboard Alokasi (menu baru di Penerimaan): card per jenis alokasi berisi jumlah dan total nominal yang belum diproses, umur tertua, dan sebaran umur. Filter rentang tanggal, Company, Bank. Export to Excel mengikuti filter (tanpa filter = semua).
  • Pengembalian Kasbon: seperti Penerimaan Piutang. Baris rekening koran yang dialokasikan Pengembalian Kasbon jadi draft di menu Expense → Verifikasi Pengembalian Kasbon. Finance klik Proses Verifikasi dan memilih sendiri Expense Report-nya (tidak ada pencocokan otomatis); perbandingan bank, tanggal, nominal dengan bukti user membantu 3 checklist. Jurnal tetap satu (Dr Bank / Cr Piutang Lain-lain Konsultan). Tampungan Pengembalian Kasbon jadi daftar status berjalan.
  • Autodebet pembayaran lewat Transaksi Bank: arah (keluar/masuk) mengikuti debit/kredit rekening koran, user cukup memilih COA lawan. Di sistem pilihan COA lawan = seluruh COA master (mockup memberi contoh 2103-01-07 Hutang Asuransi BPJS Ketenagakerjaan dan 5101-01-03 Biaya Pengeluaran Lainnya). Kalau tagihannya sudah tercatat sebagai hutang, pilih akun hutangnya supaya tidak dobel beban.
  • Akun lawan Transaksi Bank dipilih manual oleh user (tidak ada isi otomatis dari kata kunci). Form menampilkan preview jurnal dan arah CR/DB rekening koran.
  • Mulai bersih tanpa data awal (mis. go-live per Desember): semua Mutasi dan Transaksi Bank dibuat dari rekening koran. Tidak ada pilihan menautkan ke transaksi / realisasi manual lama.
  • Transaksi Bank hanya dari rekening koran (input manual ditutup); satu baris rekening koran = satu transaksi (bunga, pajak bunga, biaya admin, biaya transfer). Form memakai label Bank (COA Tujuan) dan Akun Lawan (COA Asal) sesuai jurnal sistem.
  • Menu dipisah: Mutasi Bank (Request Mutasi, Approval Mutasi), Transaksi Bank (Data Transaksi Bank). List Mutasi dihapus: realisasi (MTR) dan jurnal per sisi dilihat di tampungan Mutasi (kolom Proses, link Lihat jurnal); status request di Request Mutasi menjadi Terealisasi MTR-…. Di kode tetap satu modul request_mutasi.
  • Target Accounting dihapus dari Request Mutasi dan Transaksi Bank. Buku jurnal ditentukan rekening: sisi keluar di buku company bank asal, sisi masuk di buku company bank tujuan. Form menampilkan company otomatis, mis. "SUSTAIN → STM (antar company)".
  • Proses Mutasi / Transaksi Bank dimulai dari tombol di tampungan, membuka form modul yang sudah terisi.
  • Mutasi diproses dengan memilih Request Mutasi di kedua sisi (bukan memilih MTR); satu tombol Proses Mutasi.
  • Jurnal mutasi dibuat per sisi, masing-masing di buku company rekening korannya, saat baris itu diproses. Mockup memakai usulan jurnal versi awal; usulan fix menyusul.
Perlu dikonfirmasi
  • Mutasi tanpa Request Mutasi: boleh dibuat langsung dari rekening koran atau tidak (menunggu jawaban atasan).
  • Usulan fix jurnal mutasi (akun Piutang/Hutang antar company, akun Kas/Bank dalam Perjalanan) dan COA lawan Transaksi Bank (bertanda *).
  • Prosedur Finance bila nominal/tanggal bukti user beda dengan rekening koran (sementara mengikuti 3 checklist sekarang).
  • Proses lanjutan Pembayaran belum dibahas.
